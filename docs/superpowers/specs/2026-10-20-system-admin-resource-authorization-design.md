# Xelora 系统管理员资源级授权设计

**日期：** 2026-10-20

**状态：** 待评审

**仓库基线：** `E:/Xelora/WeKnora`，分支
`feat/xlsx-visual-parser`，提交 `1badaad383892d8ace787fff7543007c932eae99`

## 决策

系统管理员（`User.IsSystemAdmin == true`）是平台级身份，不受租户、组织、
工作空间、资源创建者或当前活动空间限制。系统管理员对平台内容的读取、
创建、修改、复制、移动、删除、检索和共享管理拥有最高权限。

实现采用资源级授权，不采用全局删除租户条件或全局绕过仓库过滤的方式：

1. 认证层只信任 JWT 认证得到的系统管理员身份。
2. 按资源 ID 全局加载资源，再判断调用者是否为系统管理员。
3. 系统管理员通过授权后，将操作的租户上下文切换到资源实际所属租户。
4. 列表接口对系统管理员返回全平台资源，并按资源各自租户解析元数据。
5. 非系统管理员的租户隔离、组织共享、资源可见性和只读规则保持不变。
6. 前端系统管理员权限只用于正确呈现可执行操作，最终授权仍由后端执行。

“最高权限”表示绕过租户级和资源级授权限制，不表示跳过数据完整性约束。
例如，知识在被复制或移动时仍须满足类型、嵌入模型和向量存储兼容性约束。

## 目标

- 系统管理员无需加入目标租户或组织，即可访问任意租户的资源。
- 系统管理员可在知识库页面执行上传、新增、编辑、复制、移动、清空、
  删除、标签、FAQ、分块、检索和共享管理，无论知识库属于哪个租户。
- 系统管理员列表可见全平台资源，而不是只看到当前租户及显式共享资源。
- 跨租户操作使用资源所属租户的模型、文件服务、向量存储、标签和索引。
- 创建类操作的默认目标仍是系统管理员当前活动租户；显式指定目标时使用目标租户。
- 异步任务明确携带来源租户和目标租户，旧任务载荷仍可兼容执行。
- 非系统管理员的授权行为、错误语义和数据可见范围不发生回退。
- 全平台资源按统一规则完成审计和接入，不遗留仅修好知识库页面的局部状态。

## 非目标

- 不将系统管理员身份等同于普通租户 `Owner`；租户角色只用于兼容现有 UI 和路由。
- 不为普通租户管理员扩大跨租户权限。
- 不在仓库层为所有查询永久移除租户谓词。
- 不向系统管理员回显凭据明文、密码、Token、私钥或未脱敏的密钥配置。
- 不改变资源业务规则，例如知识库类型、嵌入模型、向量存储和文件存储兼容性。
- 不自动合并或覆盖当前工作树中的 MCP、部署配置等无关未提交修改。

## 信任边界

`SystemAdminContextKey` 是唯一的平台管理员授权标记，只能由 JWT 用户认证路径
根据数据库中的 `User.IsSystemAdmin` 设置。

- API Key 认证路径必须显式设置 `SystemAdminContextKey=false`。
- Embed、MCP Endpoint、IM 等非 JWT 认证路径必须继续显式设置非管理员身份。
- 客户端提交的 `is_system_admin`、租户 ID、组织 ID 或请求头不得提升权限。
- 系统管理员路由守卫、资源守卫和服务层授权必须读取同一个可信标记。
- `resolveTenantRole` 为系统管理员返回临时 `Owner` 仅用于既有角色守卫兼容；
  新授权逻辑不得把“临时 Owner”当作平台管理员判据。

## 租户上下文模型

现有 `TenantIDContextKey` 同时承担“调用者活动租户”和“当前操作租户”，无法可靠
支持跨租户资源操作。设计引入两个明确语义：

- `CallerTenantIDContextKey`：认证时的调用者活动租户，在请求生命周期内不可改写。
- `TenantIDContextKey`：当前操作租户，资源加载后可改写为资源实际租户。

认证中间件同时写入两个键。资源级授权通过后，授权层负责：

1. 设置 `TenantIDContextKey` 为资源租户。
2. 同步 Gin 中的租户键和 `c.Request.Context()`。
3. 加载并写入资源租户对应的 `TenantInfoContextKey`。
4. 保留 `CallerTenantIDContextKey`，供创建、复制默认目标和权限展示使用。

平台级、无租户资源使用 `tenant_id=0` 时，不得将 `TenantIDContextKey` 改写为 0
后继续调用要求正租户的服务。此类资源由平台管理员专用服务路径处理。

## 资源授权契约

每个带租户或用户所有权的资源应提供两类能力：

- 全局按 ID 加载资源，不受调用者当前租户限制。
- 返回资源授权所需的最小元数据，例如资源 ID、资源类型、租户 ID、
  创建者、可见性和共享状态。

统一判定顺序为：

1. 全局加载资源；不存在时返回资源类型的标准 404。
2. 读取可信系统管理员标记。
3. 系统管理员：授予最高资源权限，记录资源租户并切换操作上下文。
4. 非系统管理员：执行现有租户、创建者、可见性、组织共享和智能体共享判定。
5. 授权失败时保持现有 401、403、404 语义，避免为非管理员制造新的枚举入口。
6. 授权成功后，所有后续查询、写入和异步任务使用资源租户上下文。

不为全部资源建立一套巨型通用框架。优先在现有 middleware、handler 和服务中
抽取小型共享上下文与授权辅助函数，再由各资源适配器提供全局加载和授权信息。
这样既能统一安全规则，也不会把不同资源的业务授权逻辑强行塞进同一实现。

## 列表与元数据

系统管理员的列表接口返回全平台资源。资源列表中的租户相关元数据必须按每行
资源的实际租户解析：

- 不得因为资源租户不同于调用者租户就统一标记为 `shared`。
- 批量解析按租户分组，避免逐行查询，也避免错误复用调用者租户。
- 文件存储、向量存储、模型、创建者、共享数和分类等富信息按资源租户加载。
- 凭据类资源只返回脱敏后的状态和展示信息。
- 标准资源列表、共享资源列表、智能体可见资源列表和管理入口使用同一套
  系统管理员可见性规则，避免同一资源在不同入口显示不同能力。

非系统管理员仍使用现有可见资源查询和共享元数据策略。

## 写操作与目标租户

访问现有资源时，来源租户由资源决定。创建新资源时，默认目标租户由
`CallerTenantIDContextKey` 决定。

- 系统管理员在租户 `10011` 编辑租户 `10000` 的知识库时，读取、索引和文件操作
  使用租户 `10000`。
- 系统管理员在租户 `10011` 新建知识库时，新知识库默认属于租户 `10011`。
- 复制知识库且未指定目标知识库时，副本默认属于调用者活动租户。
- 明确指定目标资源时，创建和写入使用目标资源所属租户。
- 跨租户复制到新知识库时，不得继承目标租户无权拥有的源租户向量存储；
  应使用目标租户默认向量存储并重新解析，或在源目标物理存储兼容时复用索引。
- 更新和删除语句仍包含资源 ID 与资源租户，防止错误跨表修改。

## 知识库与知识完整链路

### 路由门禁

`RequireKBAccess` 继续作为路径知识库 ID 的统一门禁。系统管理员通过时：

- 权限结果至少为 `OrgRoleAdmin`。
- `EffectiveTenantID` 为知识库实际租户。
- Gin 和 request context 同时改为知识库租户。
- 下游仍可读取 `KBAccessContextKey`，不得再次被调用者租户拒绝。

### Handler 直接校验

`validateKnowledgeBaseAccessWithKBID` 等可不经过路由门禁直接调用的路径必须具备
相同的系统管理员分支。不得只修复 `RequireKBAccess` 而遗漏查询参数、请求体或
服务内部调用。

`resolveKnowledgeAndValidateKBAccess` 必须先全局加载知识条目，再对系统管理员
直接返回知识条目租户上下文。普通用户的组织共享和智能体共享判定保持原顺序。

### 清空、删除与复制

- `ClearKnowledgeBaseContents` 不得再比较知识库租户与调用者租户；
  系统管理员只需通过资源授权，后续列表和删除任务使用知识库租户。
- `DeleteKnowledgeBase` 在软删除前读取知识库，任务载荷使用知识库租户、
  该租户的有效检索引擎和向量存储快照。
- `ProcessKBDelete` 使用载荷中的资源租户加载知识、模型、文件和向量资源。
- `CopyKnowledgeBase` 分离源租户、目标租户和源/目标资源查找。
- 复制到已有目标时，以两个资源各自租户执行兼容性检查和存储服务解析。
- 复制到新目标时，以 `CallerTenantIDContextKey` 作为默认目标租户。

### 移动

`MoveKnowledge` 对系统管理员可同时选择不同租户的源知识库和目标知识库：

- 全局加载源、目标知识库。
- 系统管理员绕过租户匹配，但仍执行知识库类型和嵌入模型兼容性检查。
- 源知识条目必须在源知识库中且处于完成状态。
- 任务载荷携带源租户和目标租户。
- `reuse_vectors` 仅允许源目标共享同一物理向量存储。
- 跨向量存储必须使用 `reparse`，重新解析任务使用目标租户和目标知识库配置。
- 移动完成后知识条目和分块的 `TenantID`、知识库 ID 和向量索引必须一致。

### 标签、FAQ、分块和检索

所有以知识库或知识 ID 为入口的标签、FAQ、分块、下载、搜索、索引和检索路径
必须先完成所属知识库资源授权，再使用知识库租户。系统管理员搜索可覆盖全平台
知识库；普通用户的搜索范围仍由当前租户、共享和智能体可见性决定。

### 前端

知识库详情、列表卡片、编辑器、FAQ 和批量管理使用统一的系统管理员能力判定：

- 系统管理员可见上传、新增、设置、标签、打印、复制、移动、清空和删除操作。
- `read_only`、`my_permission` 和跨租户 `shared` 展示不得覆盖系统管理员能力。
- 跨租户资源可以保留来源租户提示，但不能按只读共享资源渲染。
- 前端能力函数覆盖现有 `can_create_knowledge_base`、`can_create_agent` 和
  `can_bind_model`，未知能力默认不授予。

## 异步任务约定

以下载荷增加明确来源和目标租户：

```go
type KBClonePayload struct {
    SourceTenantID uint64 `json:"source_tenant_id,omitempty"`
    TargetTenantID uint64 `json:"target_tenant_id,omitempty"`
    TenantID       uint64 `json:"tenant_id,omitempty"` // 兼容旧任务
    // 既有字段保持不变
}

type KBDeletePayload struct {
    SourceTenantID uint64 `json:"source_tenant_id,omitempty"`
    TenantID       uint64 `json:"tenant_id,omitempty"` // 兼容旧任务
    // 既有字段保持不变
}

type KnowledgeMovePayload struct {
    SourceTenantID uint64 `json:"source_tenant_id,omitempty"`
    TargetTenantID uint64 `json:"target_tenant_id,omitempty"`
    TenantID       uint64 `json:"tenant_id,omitempty"` // 兼容旧任务
    // 既有字段保持不变
}
```

新任务必须写入新字段。Worker 解析规则为：

- `SourceTenantID` 非零时使用它；否则回退到 `TenantID`。
- `TargetTenantID` 非零时使用它；否则回退到源租户。
- 删除任务只有来源租户，回退语义与克隆源租户相同。

源租户和目标租户必须分别加载 `TenantInfoContextKey`。文件服务、模型、向量存储、
标签、索引、文档解析和摘要等下游调用不得继续使用单一遗留 `TenantID`。

## 全平台资源覆盖

系统管理员最高权限必须经过逐资源审计后接入。最低覆盖范围如下：

| 资源域 | 必须验证的能力 |
| --- | --- |
| 知识库、知识、分块、FAQ、标签、分类 | 全平台列出、读取、上传、编辑、删除、清空、复制、移动、检索 |
| 智能体与智能体共享 | 全平台列出、查看、创建、编辑、删除、共享和引用知识库 |
| 会话、消息、收藏、Wiki | 跨租户读取和修改，保持会话所有者与租户元数据一致 |
| 数据源与数据源凭据 | 跨租户查看、测试、同步、编辑、删除和脱敏展示 |
| 模型与模型凭据 | 跨租户查看、绑定、测试、编辑、删除；平台默认模型规则保持 |
| 向量存储 | 跨租户列出、连接、更新、删除、索引和重解析 |
| 网页搜索服务与凭据 | 跨租户查看、测试、编辑、删除和脱敏展示 |
| MCP 服务、凭据与端点 | 跨租户查看、测试、编辑、删除及关联智能体 |
| 组织、租户、成员与 RBAC | 全局列出和修改；仍保留最后系统管理员等安全约束 |
| 知识库和智能体共享 | 全局查看、创建、修改和撤销共享 |
| Embed 与 IM 渠道 | 跨租户查看、创建、更新、停用和删除 |
| 初始化、系统设置与平台配置 | 继续使用系统管理员路由，并验证无租户上下文依赖 |

每个资源域接入时至少检查列表、详情、创建、更新、删除、凭据操作和异步任务。
共享入口不能成为绕过统一资源授权的旁路。

## 审计与安全

- 系统管理员跨租户写操作和破坏性操作应写入审计日志，包含操作者、动作、
  资源类型、资源 ID、来源租户、结果和必要的非敏感摘要。
- 审计失败采用仓库现有 best-effort 语义，不得把已完成操作伪装成失败；
  高风险操作是否要求审计成功后再提交由后续实现计划明确选择。
- 凭据响应始终脱敏。系统管理员可以更新或轮换凭据，不代表可以读取原始 Secret。
- 系统管理员仍不能撤销自己或最后一个系统管理员。
- 资源不存在、非管理员越权和系统管理员合法访问必须在日志和响应中可区分。

## 错误处理

- 资源 ID 无效或不存在：返回该资源的 404，不因调用者是系统管理员而变成 500。
- 资源存在但业务约束不满足：返回明确 400 或冲突错误，不伪造授权失败。
- 跨租户上下文加载失败：返回 503 或内部错误，不得回退到调用者租户继续执行。
- 异步任务租户字段缺失且旧字段也为零：任务失败并记录诊断，不默认使用任意租户。
- 向量存储不可用：按现有服务语义返回不可用或重试错误，不静默改写到其他存储。
- 前端权限与后端不一致时以后端结果为准，并记录可观测诊断。

### 第二阶段：内容与协作资源

每个阶段保持非管理员行为不变，并在进入下一阶段前完成自动化测试和远程验收。
后续阶段可以单独制定实施计划，但不得把第一阶段完成描述为全平台需求已完成。

## 风险与缓解

- **隐藏租户假设：** handler 和服务中仍有大量直接读取租户 ID 的位置。
  通过逐资源审计、跨租户夹具和路由覆盖测试降低遗漏风险。
- **后台任务串租户：** 新载荷必须同时携带来源和目标租户，并验证旧任务回退。
- **向量数据损坏：** 只有共享物理向量存储时允许复用索引，其余强制重新解析。
- **凭据泄露：** 管理权限与 Secret 明文读取权限分离，响应保持脱敏。
- **非管理员回归：** 不修改全局仓库租户过滤；所有管理员分支必须在资源加载后进入。
- **工作树冲突：** 只在相关文件做最小修改，保留用户现有未提交改动，不执行清理或重置。
